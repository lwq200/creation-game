# 多 Agent 协作经验（来自《数学基础》一册实战沉淀）

> 本文件沉淀一次完整的多 agent 协作写书（《数学基础》4 幕 17 章 + 补强 + 全量重排）中积累的经验教训。供后续多章/多 agent 协作时复用。

## 一、协作分工模式

推荐的角色分工（一个团队一次写一部书）：

| 角色 | 数量 | 职责 |
|------|------|------|
| main（总协调） | 1 | 规划蓝图、分派章节、汇总统稿、全量重排、统一标准 |
| writer（章节作者） | 2-5 | 每个 writer 负责认知上连贯的 2-3 章（如数/逻辑、集合/函数、微积分） |
| reviewer（评审） | 1 | 按 skill 标准评审（内容+技术准确性+AI味+对话不套路化），提意见，复审 |

要点：
- **分批推进**：按幕分批次（如批1地基、批2变化），每批写→评→改→定稿后再启动下一批。避免一次性并行过多章导致标准失控。
- **writer 按认知依赖分组**：让一个 writer 写主题连贯的连续章（如多元微积分+最优化），保证内部风格一致、衔接自然。
- **reviewer 必须读 skill 标准**：评审前先读 SKILL.md + 章节写作规范 + 人物设定，建立风格基线。

## 二、对话不套路化的实战铁律（本次反复踩坑总结）

跨章雷同是最容易被忽视、但评审必抓的问题。以下是本次实际抓出的雷同类型与对策：

### 1. 引子反应词雷同
**踩坑**：多章引子都用"我一愣""我噎了一下""我愣住了"，跨章撞车。
**对策**：每章引子的角色反应词必须**全书唯一**。本次 17 章最终形成各不相同的一组反应词，如：我一愣/我眨了眨眼/我噎了一下/我手一顿/我梗了一下/直勾勾盯着/愣是没憋出/咬住下唇/眼皮一跳/心口一紧/低头看了看盒子/我眼睛一亮/手微微一缓/握旋钮的手顿在半空/嗓子发涩/抿了抿嘴/喉结一滚。
**评审动作**：reviewer 必须**跨章比对**引子反应词，而非只看单章。写作规范第 4 条「对话不套路化」的"一句话标准"要严格执行：抽两章同一角色的话，若一半句式雷同即判套路化。

### 2. 落点/收束句式雷同
**踩坑**：多章落点都用"绕了一大圈，回到你最初那个…"句式，批次内 3-4 章连续使用。
**对策**：落点收束也要换招——有的让造物主闭眼口述全章推导、有的回扣引子物品动作、有的用一个反例收尾。**若同一句式在多章出现，视为套路化，必须各自换招。**

### 3. 表扬句式雷同
**踩坑**："你亲手把…推出来了""你自己把这个…顺出来了""你把钥匙摸出来了"在多个 writer 间反复出现。
**对策**：老谟的表扬/点评也要轮换，避免"你亲手/你自己…出来了"这类庆祝范式。可用"这就不赖了""你自己掂量""这名字你没白起""把 sin 的底裤扒了个干净"等多样表达。

### 4. 强调句式重复
**踩坑**：某章"复杂函数，变成了加减乘除"出现 5 次以上。
**对策**：核心强调语全章控制 ≤2 次，其余换说法。

## 三、技术准确性评审要点（本次补强重点）

写作和评审都必须验证计算正确性，以下是本次抓出的数值错误：

### 1. 代码注释的期望输出必须实测
- 曾出现 Python 注释写的梯度期望值算错（0.9089 实为 0.7241），读者照跑对不上。
- **对策**：writer 写【实现思考】代码时必须亲手运行或手算核对注释里的期望输出；reviewer 要抽验关键数值（导数值、积分值、特征值、期望、熵）。

### 2. 概念表述的歧义要分清
- 期望 vs 样本均值：期望是分布的理论中心（总体属性），样本均值是估计值，"相等"只在长期平均意义下成立。不能混为一谈。
- MLE 的"更可能"：要说清是"更可能解释数据"（似然）而非"更可能为真"（后验，需先验）。
- 浮点比较：`==` 会翻车，要用 `abs(a-b)<eps`（容差）或 `np.isclose(a,b,rtol,atol)`（相对+绝对误差合成）。

### 3. 定理的条件要讲清
- Taylor 展开有收敛半径：ln(1+x) 只在 |x|<1 可信，sin/eˣ 全数轴收敛是特例。
- 幂级数不是对整个数轴都成立，必须点明"收敛半径"。
- 特征值正定 ⟺ 二次型恒>0（对称矩阵）。

## 四、宁深勿浅的正确执行

**宁深勿浅 = 讲得深，不是限制知识点数量。** 判断标准：读者看完一章，对每个出现的知识点是"真懂了能造"，还是"听了个名字就走"——后者即浅。

- 不因"知识点超过 N 个"就判超标。
- 每个知识点都要配推导或算例，讲透。
- 若某点确实无法当章讲透，才考虑拆章或降为"预告清单"（要说明去向，不是偷懒）。

## 五、全量重排的注意事项（本次踩坑总结）

当章节顺序因插入新章而重排时，必须同步处理：

1. **文件重命名**：用脚本两步法（先移临时名避免目标名冲突，再移最终名）。映射要精确。
2. **标题更新**：每个文件第一行 `# 第 NN 章` 的章号要同步改。
3. **正文章号引用**：正文里"第 X 章"交叉引用（如"承接第 9 章"）要按映射批量替换。**注意正文用一位数字（第 9 章）而标题用两位（第 09 章）**，正则要兼容 `\d{1,2}`。替换要跳过文件自己的标题行。
4. **预告衔接**：重排后每章末尾"预告"指向的下一章可能变了，要逐个检查并重写预告，让叙事链连贯。受影响的往往是插入点前后的章。
5. **清理套路句式**：重排是统一处理"绕了一大圈"等残留句式的好时机。

## 六、标准变更的同步

当用户澄清/修正某个标准（如"宁深勿浅"定义）时，必须：
1. 更新 SKILL.md 和所有 references 里的相关表述
2. **同步给所有协作 agent**（writer、reviewer），明确告知新口径
3. 让 reviewer 用新口径重新评估此前按旧口径的判定
4. 否则 agent 会继续按旧标准执行，造成返工

## 七、多 agent 协作常用话术

- 派任务时：给出文件路径、清晰的范围（只增不改/新增章）、硬性标准（轮数/字数/宁深勿浅/不套路化）、术语命名时机。
- 评审时：让 reviewer 给"逐维度评分 + 问题清单（引原文）+ AI味 + 结论（通过/需修改）"。
- 修订反馈：把 reviewer 意见原样转给 writer，标注必改/可选；改完发 reviewer 复审。
- 关闭：全书完成后向所有 agent 发 shutdown_request，全部确认后再 team_delete。


## 八、三专家评审闭环流水线（来自《概率统计与信息》册实战沉淀）

> 本节沉淀一次**升级版**团队协作：把"单一 reviewer"升级为**三名专职评审专家**，与多名并行作者组成「创作 → 三专家评审 → 修改 → 复审 → 定稿」闭环。一次成功跑完 9 章（概率册），全册 20+ 证明可复写、全部数值经亲手核算、学派中立双轨达标。**这是后续多册教材协作的推荐模式。**

### 1. 角色分工（实测有效配置）

| 角色 | 数量 | 职责 | 谁适合 |
|------|------|------|--------|
| main（主笔/首席架构师） | 1 | 把控全书哲学与人设、起草**样板章**、分发评审、统稿打包 | 最懂这本书灵魂的人 |
| 严格性首席（rigor-chief） | 1 | 每章「严格化走廊」把关：定义精确、定理带全前提、证明无跳、可复写、反例边界 | 数学系博士/教授（分析/代数方向） |
| 习题与工程设计师 | 1 | 每章「计算训练场」把关：中大型计算题梯度、完整分步解答、**数值亲手复核**、Python 实测 | 有教学经验的数据科学/计算机工程师 |
| 跨学科顾问 | 1 | 学派中立（贝叶斯/频率）、历史准确、节奏平衡、可计算性立场 | 统计学家/理论计算机科学家 |
| writer（作者） | 2-3 | 按样板标准并行创作连续章组 | 熟悉 skill 标准的写作者 |

**关键**：main 必须先写**样板章**（第 01 章）并让它**通过三专家评审定稿**，再让作者照它写后续章——样板章是全册质量基线的锚点，作者全部"对标第 01 章"。

### 2. 并行流水线（实测节奏）

```
阶段A：main 写样板章 → 三专家评审 → 修改 → 复审定稿（锚定质量标准）
阶段B：并行派 3 个 writer（基础/统计/信息三组），同时三专家对样板章建立评审口径
阶段C：每组完成 → 发给三专家并行评审（每个专家审自己维度）
阶段D：main 汇总三份意见 → 派给对应 writer 修改（标注必改/可选）
阶段E：专家复审 → 通过则定稿，否则循环 D-E
阶段F：全册评审闭环 → 统稿（补工程案例/答案速查页/交叉引用核查/打包）
```

### 3. 本次踩坑与对策（必读）

**① 评审基于"旧快照"误报**
- 现象：两位专家都报"第 01 章第 4 轮仍在演证明"，但磁盘实际已是精简版——它们读到了旧快照/缓存。
- 对策：main 收到评审意见后，**先读磁盘核实**，再决定采纳还是澄清；向专家说明"你读到的可能是旧快照"，并请其复核。**别盲改。**

**② 红线 1（对话不演证明）会复发**
- 现象：第 01 章第 4 轮修过后，第 04 章第 2 轮又完整"演"了方差公式证明，第 06 章原第 3/4 轮也演了后验公式。
- 对策：红线 1 是"全册"红线，不是"单章"红线——**每次评审都专项检查**；修订样板章时，把"对话只推'为什么想到这步'，公式证明进走廊"写成标准话术，随任务派发给所有 writer。

**③ 学派中立最易翻车的三处**（统计册重点）
- 置信区间："工序长期 95% 覆盖"（频率，主语=区间）vs"μ 有 95% 概率落这里"（贝叶斯可信区间，主语=μ）——必须显式区分。
- P 值："原假设下看到如此极端数据的概率"≠"原假设为真的概率"。
- MLE："更可能解释数据（似然）"≠"更可能为真（后验，需先验）"。
- 对策：cross-advisor 专职盯这三处 + 两章互相引用不判胜负；"随机性安在谁身上，谁就是那一派的主语"是本册最有效的收束语。

**④ 数值必须亲手复核（专家互验）**
- 现象：代码注释期望值、KL 不对称值、CDF 极限求和值等，作者自报可能算错。
- 对策：exercise-designer 对**每个终值**亲手核算；main 对重点数值（蒙特卡洛模拟、链式一致 H(X,Y)=H(X)+H(Y|X)）**实机运行验证**（如 numpy 实测 0.9462≈95%）。

**⑤ 终章预告悬空**
- 现象：第 09 章是终章，但预告写了"下一章"（指不存在的章），且引用了已讲过的内容造成顺序错位。
- 对策：统稿前**核查每章预告与真实章序**；终章预告改为"全册收束"措辞。

**⑥ 跨章/跨册引用混淆**
- 现象：本册"第 08 章（熵）"与样书"第 8 章（数列与级数）"易混淆；"上一章证过单调性"实际在第 01 章而非第 02 章。
- 对策：统稿阶段派独立校对员做**全册交叉引用扫描**（章内引用、跨册引用、预告衔接、答案速查页对应），逐条报告。

**⑦ 提前提及的承诺要兑现**
- 现象：第 01 章承诺"可列可加性将在随机变量章正式引入"，第 03 章必须补正式公理定义闭环。
- 对策：每章出现"将在第 X 章正式引入"时，登记到统稿清单，统稿时逐条核对是否兑现。

### 4. 评审输出格式（实测好用）

每个专家按自己维度输出：
```
逐章评分表（1-10，分维度）→ 必证项核对 → 问题清单（引原文，标必改/可选）→ 结论（通过/需修改）
```
main 汇总后，把**必改项**原样转给对应 writer，**可选项**登记到统稿清单择机打磨。

### 5. 统稿清单（评审闭环后必做）

- [ ] 补 Python 工程案例并实机验证（蒙特卡洛/数值模拟）
- [ ] 答案速查页（全部计算终值，三专家复核）
- [ ] 交叉引用扫描（章内/跨册/预告/速查页）
- [ ] 提前承诺逐条兑现核对（"将在第 X 章正式引入"）
- [ ] 严格性可选项打磨（控制收敛、分部积分完整化等）
- [ ] 册 README + dist 打包（命名规范：`书名_章数_日期.zip`）

## 九、会话超长与主笔接管（来自《单变量微积分》《线性代数》两册实战沉淀）

> 本节沉淀**连续跑两册（册03 微积分 8 章、册04 线性代数 9 章）**时遇到的核心风险与对策。两册完整跑通三专家闭环；但**册04 中途团队全部成员消失**，main 被迫接管——此为新踩的最大坑。

### 1. 团队会话超长 → 成员全部消失（最严重的新坑）

- **现象**：连续多册长会话后，`send_message` 返回 "Known members: none"，所有 writer/专家/统稿员**全部失联**；且作者**已创建的文件可能是 0 字节空文件**（写入中断，如册04 Ch8）。
- **对策（main 直接接管，勿空等）**：
  1. 先用 `list_dir` + 读盘确认真实状态（哪些章完成、哪些空文件、哪些缺失）。
  2. 空文件/缺失章**由 main 亲自补写**（蓝图 + 样板章已确立标准，直接照写即可达标）。
  3. 未收的专家评审 **main 自查替代**：对照已收评审口径，逐章抽查数值（行列式、逆矩阵、特征值、SVD 等）+ 验证红线1（对话不演证明、走廊"关于对话"块、证明类型+每步依据）。
  4. 剩余统稿（答案速查页 + README）main 亲做，格式照已定稿的前册即可。

### 2. 上下文管理（"文本太长撑不住"）

- **现象**：单会话上下文被 4 册对话历史撑爆，导致响应变慢/中断/成员消失。
- **对策**：
  1. **每完成一册就向用户要新会话**，并用 `update_memory` 沉淀项目状态（进度、样板标准、经验教训），新会话开局即恢复。
  2. 分册分批推进，**不追求一次会话写多册**。
  3. 会话内控制输出篇幅：派任务给作者/专家后**静默等待**，不输出冗余进度。

### 3. 跨册"跳册"引用（新形态的引用错误）

- **现象**：册03 Ch8 终章预告写"下一册《多元微积分与凸优化》"——但按系列蓝图，册03 的下一册是**册04《线性代数》**，《多元微积分与凸优化》是**册05**。跳册了，且跳过了后者（多元）实际依赖的代数基础（矩阵/特征值）。
- **对策**：统稿阶段**对照丛书蓝图核对每册终章"下一册"表述**，必须指向真实下一册；跳过的册要说明"先过 X 册（提供基础）"再铺垫目标册。

### 4. 新的数值错误类型（linea 代数册新增）

- **行列式展开余子式符号/漏乘**：如 `det[[1,1,1],[1,−1,0],[1,0,−1]]` 第一项余子式写错得 1，正确为 **3**（余子式 det[[−1,0],[0,−1]]=1 而非 −1）。**多列展开时必须逐项核余子式。**
- **跨章同一矩阵 det 口径要一致**：Ch6 与 Ch7 共用 P=[[1,1,1],[1,−1,0],[1,0,−1]]，一处改对另一处还写旧值——**统稿时扫描同一矩阵在多章的出现，det 必须一致。**
- **σ=√λ 忘开方**：SVD 的奇异值是特征值平方根，易把 λ 当 σ。
- **PCA 忘中心化**：协方差必须用中心化后的数据算，否则均值带偏主成分。
- **含参方程组分类漏端点**：a≠某值/某值 的边界值要单独讨论。

### 5. 作者"声称已改但正文没改"

- **现象**：作者回复"已修正 =3"，但 main 读盘发现正文 L339 仍是旧值 1（只改了自报清单/草稿）。
- **对策**：**每次收到"已改"必须读盘核实**（指定行号/关键词），尤其跨章共用的数值；确认后再进复审，不轻信自报。

### 6. 跨章口径字面统一（"关于对话"块）

- **现象**：专家反复以"某章缺'关于对话'块"报口径不统一（评审可能基于旧快照，或某章确实漏）。
- **对策**：**每章走廊都单列"关于对话"块**（第 X 轮首次接触…引导式推导…正式证明在走廊定理 X），与册02/03 字面一致；main 收到"缺块"意见先读盘核实（可能在别行），再决定补/澄清。
